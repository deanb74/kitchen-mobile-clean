## What Helping Hand needs to understand before asking Andy to contribute

**The contribution question is premature not only because Andy's orientation is incomplete. It is premature because the organisational clarity about Andy's contribution is also incomplete.**

The repository contains:
- `docs/handovers/VOLUME_VIII_EXIT_CRITERIA.md`: *"Validate the inheritance model through Candidate 0 — Andy."* — This names him but does not specify how.
- `docs/previously-discussed/PD-001.md` (candidate): Describes his intended roles — but explicitly marked as candidate understanding, not formally accepted.
- No document currently states: *"In Stage 1, Andy should do X."*

Asking Andy "what do you need to begin contributing?" without Helping Hand having a clear, shared answer to "what do we need Andy to do?" puts the clarification burden on Andy. That is the wrong direction. It produces either a correct answer that cannot be recognised as correct, or an invented answer that fills the void.

The organisation needs to answer: **what does Stage 1 specifically need from Andy?** That is a founder decision, not something Andy can discover by reading.

## Does the Orientation Framework need refinement before further journeys?

**Yes — one specific refinement, not a redesign.**

The framework's five-layer structure (enduring, historical, current, candidate, unknown) emerged from Andy's observation and is a strong candidate. It does not need redesigning.

**The refinement needed:** the current-state layer needs to acknowledge that it cannot be provided by the repository alone. The repository can provide the enduring, historical, and candidate layers. The current state — what the organisation needs right now, what the founders find hardest, what Stage 1 asks of this Digital Colleague specifically — requires human input. The Orientation Framework, as currently written, does not make this distinction explicit.

The framework should distinguish between:
- **Layers the repository can provide:** enduring, historical, some of candidate
- **Layers that require a human or founder briefing:** current state, unknowns, the specific role of this DC right now

**This distinction is also the answer to Andy's question:**

> "Why was this conversation not part of my graduation?"

Because graduation ends when formation is complete, and the current-state layer cannot be provided at graduation — it is specific to the moment the DC is asked to contribute, and it changes over time. Formation is timeless. Orientation is temporal.

## Recommendation

**Three actions in order — no journey yet.**

**1. Founder decision**

Define what Stage 1 currently needs from Andy. State it explicitly. Not as candidate understanding. As the current expectation. This resolves the organisational clarity gap.

**2. Founder-to-Andy briefing**

Give Andy the completed current-state layer — what he specifically needs to know before the contribution question can be meaningfully asked. This completes the Orientation that UJ-HUM-013 began.

**3. Then UJ-HUM-014**

With the current-state layer complete, the contribution question is fair. Andy has enough to answer it. The organisation has enough to evaluate his answer.

Before further journeys, the framework (`docs/institution/DIGITAL_COLLEAGUE_ORIENTATION_FRAMEWORK.md`) should note explicitly which layers the repository can provide and which require human input.

This is the gap the framework currently leaves implicit — and it is the most important practical insight from the entire UJ-HUM-013 evidence cycle.

The smallest next evidence exercise is not a journey.

It is a conversation with the founders that UJ-HUM-013 made necessary.
