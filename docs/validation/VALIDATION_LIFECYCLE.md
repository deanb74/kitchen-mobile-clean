# Validation Lifecycle

Helping Hand now distinguishes three kinds of validation.

## 1. Engineering Validation

**Question:** Can it work?

**Evidence required:** correctness, stability, repeatability, traceability

**Owner:** Engineering

**Output:** Engineering Evidence

## 2. Human Validation

**Question:** Does it genuinely help people?

**Evidence required:** understanding, trust, clarity, practical usefulness

**Owner:** People (users, staff, mentors, domain experts)

**Output:** Human Evidence

## 3. Inheritance Validation

**Question:** Should every future Digital Colleague receive this capability?

**Evidence required:** engineering evidence, human evidence, no constitutional conflict, generalisability across professions

**Owner:** Helping Hand through governed review

**Output:** Inherited Capability

## Lifecycle

Idea

-> Engineering Validation

-> Human Validation

-> Inheritance Validation

-> Core Helping Hand Capability

## Decision rule

Engineers validate software. People validate Digital Colleagues. Helping Hand validates inheritance. Only when all three agree does a capability become part of the foundation.

This is a decision process for earned universality. A capability is not inherited because it is reusable, or because one team likes it. It is inherited because the evidence has earned that right.
