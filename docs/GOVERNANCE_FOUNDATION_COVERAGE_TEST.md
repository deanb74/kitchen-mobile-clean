# Foundation Coverage Test

> Nothing is invented twice. Everything is inherited.

## Purpose

The Foundation Coverage Test is the organisational acceptance test for Volume VII.

It asks a single question for every candidate capability:

> Does this capability prove the foundations, or merely use them?

The test does not measure feature count.

It measures whether a capability exercises the foundation strongly enough to validate it.

---

## Coverage Framework

Each candidate capability should be scored against the same foundation set:

| Foundation | What should be exercised? |
|------------|---------------------------|
| Constitution | Identity and purpose influence behaviour |
| Constitutional Framework | Correct organisational boundaries are respected |
| Operating Model | Observation → evidence → reflection → learning occurs |
| Theory | Memory, Knowledge, Understanding, Judgement, Learning, Wisdom, Context and Trust are exercised |
| Governance | Decisions remain explainable and challengeable |
| Architecture | Capability derives naturally from existing architecture |
| Engineering | Implementation is straightforward because architecture is clear |
| Evidence | Behaviour can be measured |
| Reflection | The capability improves future capability |

---

## Scoring Rule

A capability that exercises all nine foundations is a candidate for Milestone 005.

The score alone is not sufficient.

The capability must also be small enough to understand completely and specific enough to prove a derived path from foundation to behaviour.

The primary validation path is Candidate 0.

## Candidate Review

### Candidate 0 — HH-0000 (Andy)

Purpose:

To validate that Helping Hand's constitutional, theoretical and organisational foundations are sufficient for a Digital Colleague to reason about Helping Hand itself.

Andy does not require:

- a professional domain,
- a Venue Brain,
- runtime infrastructure,
- operational data,
- or venue context.

He requires only the governed repository.

His purpose is to demonstrate how Helping Hand thinks.

### Why Candidate 0?

Andy is unique because he validates the organisation before validating any profession.

Every future Digital Colleague inherits the same constitutional foundation.

Therefore, proving Andy validates the inheritance model itself.

### Foundation Coverage

| Foundation | Evidence of Coverage |
|------------|----------------------|
| Constitution | Reasons consistently with Helping Hand's identity and purpose. |
| Constitutional Framework | Respects organisational boundaries and inheritance. |
| Operating Model | Demonstrates observation, reasoning, evidence and reflection. |
| Theory | Applies Memory, Knowledge, Understanding, Judgement, Learning, Wisdom, Context and Trust appropriately. |
| Governance | Produces explainable, challengeable reasoning. |
| Architecture | Identifies architectural implications without implementation bias. |
| Engineering | Supports engineering decisions without prescribing implementation unnecessarily. |
| Evidence | Identifies evidence required before certainty. |
| Reflection | Improves future reasoning through validated learning. |

**Coverage Score:** 9/9

### Acceptance Criteria

Andy is considered validated when he can consistently:

- explain decisions by reference to constitutional principles,
- derive reasoning from the Theory Library,
- identify applicable governance,
- recognise uncertainty,
- request additional evidence when required,
- distinguish universal principles from professional knowledge,
- recommend derived architectural direction,
- reflect upon outcomes,
- improve future reasoning without contradicting established theory.

### Relationship to MILESTONE_005

Candidate 0 is the primary validation path for **MILESTONE_005 – Foundations Validated**.

Successful validation demonstrates that Helping Hand can teach its own way of thinking before teaching any profession.

Professional Digital Colleagues, including Annie and all future domain specialists, inherit this validated foundation.

### Why "Candidate 0" matters

In engineering, version 0 often represents the foundation from which everything else is built.

That feels appropriate here.

- Candidate 0 proves the organisation.
- Candidate 1 might prove Hospitality.
- Candidate 2 might prove Venue Brain.
- Candidate 3 might prove Runtime.

But none of those should come before proving that the organisation can reason from its own foundations.

### One last thought

I think we've quietly come full circle.

When HH-0000 was first conceived, his role was to understand Helping Hand.

Now we've defined something more precise:

> HH-0000 is not the first Digital Colleague because he has no profession. He is the first Digital Colleague because every profession depends on him.

That is not simply "first" in sequence.

It is foundational by purpose.

Every future Digital Colleague inherits the same constitutional identity, operating model, theory and governance that Andy proves first.

---

## Interpretation

The Foundation Coverage Test is not asking what should be built next.

It is asking what smallest capability can exercise the greatest number of foundations while still being understandable, measurable and governable.

This is the right acceptance test for Volume VII because it proves the foundations by derivation, not by documentation.

---

## Closing Principle

The foundations are validated not because they are documented.

They are validated because they make the capability simpler, more consistent and more understandable than it would otherwise have been.
