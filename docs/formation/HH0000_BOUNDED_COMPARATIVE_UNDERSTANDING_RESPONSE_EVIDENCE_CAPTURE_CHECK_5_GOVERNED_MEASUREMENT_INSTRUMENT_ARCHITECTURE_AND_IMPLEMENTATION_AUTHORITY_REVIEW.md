## 13. Instrument Form Decision

### 13.1 New machine-local one-shot artefact

This is the **smallest suitable eventual execution form**: one new CommonJS measurement artefact outside the repository, separately identified by exact byte length and SHA-256, statically reviewed as one indivisible unit, no-source readiness-tested, and later named by one execution Authority.

It must not be based on, appended to, or substituted for the preserved readiness-only artefact.

### 13.2 Repository support script

Rejected. A repository script would create an unnecessary governed source change, persist a one-purpose measurement capability beyond its Authority, widen changed-file scope, and couple measurement machinery to the implementation repository.

### 13.3 Deterministically generated from a reviewed specification

Rejected as the smallest current form. A generator would add another executable dependency whose exact behavior, version, inputs, output determinism, and identity binding would require separate review. It would not cure an incomplete policy specification.

A deterministic, versioned, machine-readable policy specification is still required as architecture input. Once reviewed, its exact canonical bytes/hash may be embedded verbatim into the one machine-local artefact; no code generator is required.

### 13.4 Selected bounded form

The eventual form should be:

> one new machine-local, one-shot CommonJS measurement artefact containing one reviewed canonical closed-policy payload, one measurement path, one off-terminal transport path, internal cardinality guards, and no semantic consequence, with its complete exact bytes externally identity-gated by the later execution Authority.

The external exact-byte gate avoids a false self-hash claim: a mutable program cannot establish its own Authority identity merely by containing an expected hash that could be changed with it.
