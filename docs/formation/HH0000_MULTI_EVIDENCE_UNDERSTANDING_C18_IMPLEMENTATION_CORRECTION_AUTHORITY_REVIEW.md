## 3. Exact Correction Boundary Analysis

### 3.1 Projection necessity validation

**Established defect:** Projection reason and scope can be substantially caller-asserted. Shape agreement can therefore make projection routine without proving reference insufficiency.

**Minimum authorised correction:**

1. keep both candidate and held-out sides reference-only by default;
2. remove the ability of a general record caller to self-authorise projection merely by supplying a reason, scope, dimensions, and length;
3. make projection admission an internal C18 evaluation result reached only after an attributable reference-only attempt;
4. bind admission to exactly one side, one immutable primary reference, one identified comparison rule, and only the material dimensions selected by that rule;
5. preserve only the three already accepted closed necessity concepts;
6. derive or validate projection scope from the exact referenced proposition/criterion and governed rule rather than trusting arbitrary matching scope strings;
7. record that reference-only evidence failed for the selected closed reason and that the projection is evaluator-authored, does not replace the referenced value, and excludes surrounding account, assessment, requirement-subtree, and source-person content;
8. impose a fixed bounded scalar representation and reject empty, excessive, non-scalar, broad, combined-side, open-reason, convenience, readability, debugging, preference, and future-use projections;
9. prohibit post-finalization admission or projection changes;
10. when C18 cannot establish necessity or cannot form the admitted minimum projection, produce `COMPARISON_INSUFFICIENT` with the exact limiting reference and closed uncertainty reason; do not widen capture.

For the current comparison rules, no production projection may be enabled merely to satisfy a synthetic acceptance case. If no governed rule and C18-controlled reference-failure path establish necessity, reference-only or `COMPARISON_INSUFFICIENT` is the required behavior.

This correction may reshape the C18-local construction/validation API and its synthetic admission fixtures. It may not create a general projection service, free-form rationale, semantic logger, or rule meaning not already settled by the design.

### 3.2 Exact Section 12 failure classes

**Established defect:** Distinct semantic limits collapse into technical `INCOMPLETE`, and production can reduce incomplete evidence to a caught mechanical failure.

**Minimum authorised correction:** Implement the existing Section 12 distinctions without adding a new status class:

| Failure boundary | Required class |
| --- | --- |
| Candidate capture identity or immutable candidate value absent before comparison | `NOT_EVALUATED`; held-out comparison does not begin |
| Held-out assessment identity/version/verified hash absent | `NOT_EVALUATED` |
| Comparison rule unavailable before comparison | `NOT_EVALUATED` |
| Candidate or held-out primary reference missing after comparison begins | `COMPARISON_INSUFFICIENT` |
| Required material dimension, observation, inference, or support reference unavailable | `COMPARISON_INSUFFICIENT` with exact limiting reason/reference |
| Necessary projection unavailable or inadmissible | `COMPARISON_INSUFFICIENT` |
| Disposition, uncertainty state, finalization prerequisite, or C12/C16/C20 linkage lost from an otherwise constructed record | visibly `INCOMPLETE` |
| Adverse or unavailable C21 finding | separate contamination/not-determinable package use; C18 disposition unchanged |
| Package omission or C23/C24 failure | separate preservation-incomplete/non-reviewable evidence; no semantic default |

The correction may use distinct closed record variants or structures to express the already accepted states. It must preserve observation, inference, disposition, evaluator condition, technical state, contamination, and preservation as separate concepts. It must not invent candidate failure, held-out correctness, evaluator correctness, material difference, certainty, or new status architecture.

Where the accepted design requires attributable evidence, a thrown error or opaque mechanical fail alone is insufficient. The package boundary must be able to retain a visibly not-evaluated, insufficient, or incomplete C18 outcome under its accepted fail-closed state without presenting it as a complete finding.

### 3.3 Attributable incomplete preservation

**Established defect:** The incomplete result clones arbitrary submitted input, including forbidden fields and rejected semantic payloads.

**Minimum authorised correction:**

1. construct incomplete evidence from an explicit allowlist of fields independently validated as established;
2. preserve the record/cycle identity and exact valid provenance references actually established;
3. preserve closed failure reasons and, where safely established, the precise comparison phase reached;
4. preserve valid C12/C16/C20 identities only when independently validated;
5. omit rather than echo unknown fields, rejected projections, invalid disagreement content, caller-forged finalization/seal fields, chain-of-thought-like content, broad copies, non-scalar values, and arbitrary submitted input;
6. deep-freeze the incomplete record;
7. prevent incomplete evidence from satisfying a complete/finalized type or package claim;
8. prohibit reconstruction, default filling, C21 repair, or post-handoff enrichment.

The governing rule is:

> An incomplete record preserves what is established, not everything submitted.

No diagnostic dump, rejected-payload mirror, or unrestricted `input`/`metadata`/extension bag is authorised.

### 3.4 One-value comparison cardinality

**Established defect:** Primary candidate references can be grouped even though the authorised unit is one candidate-value / one held-out-requirement comparison.

**Minimum authorised correction:**

1. make the primary candidate-value reference singular;
2. make the primary held-out-requirement reference singular;
3. bind one record identity, evaluator, rule, material-dimension set, observation, inference, disposition, disagreement, uncertainty, and projection admission to that one pair;
4. keep separately attributable support/evidence references distinct from the singular primary values;
5. where the existing evaluator compares a bounded structured value, reference that exact immutable structured value once rather than listing multiple internal fields as independent primary values;
6. where multiple independent candidate values are genuinely compared, emit independent records rather than aggregating semantic layers;
7. reject zero or multiple primary references at validation.

This correction changes evidence attribution only. It must not change candidate output, held-out requirement meaning, comparison-rule meaning, or the evaluator's existing match/mismatch semantics.

### 3.5 Exact C20/C21 identity linkage

**Established defect:** C18 carries a generic invocation descriptor rather than an exact C20 event identity, and package-level C21 finding identity association is absent.

**Minimum authorised correction:**

1. give the existing C20 record and relevant C18 invocation event stable mechanical identities sufficient for exact reference;
2. let C18 store only the exact C20 invocation/event identity available at finalization;
3. give the existing C21 assessment/finding a stable mechanical identity sufficient for package association;
4. let package assembly associate C18 record identity, C20 record/event identity, and C21 finding identity after C21 exists;
5. validate identity presence and correspondence without copying chronology, contamination findings, semantic content, or rationale between records;
6. keep C18 finalization earlier and distinct from C20 sealing and C21 assessment;
7. keep adverse C21 state separate from and unable to rewrite C18 semantic disposition;
8. keep C22 limited to opaque status and identity/availability routing;
9. leave C23/C24 whole-package bytes, preservation identity, and integrity responsibilities unchanged.

Adding stable identity fields and identity-only references to the existing C20/C21 records is within their accepted mechanical provenance responsibilities. Any need for C20/C21 to interpret C18 semantics, or C18 to determine contamination, is outside this authority and triggers architecture re-entry.

### 3.6 Privacy-safe closed fields and semantic consistency

**Established defect:** Disagreement alternatives are unrestricted strings, forbidden payloads can survive in incomplete records, and malformed cross-layer combinations can finalize.

**Minimum authorised correction:**

1. retain closed disagreement presence/status;
2. make alternatives reference-first through exact bounded identities/references;
3. permit a bounded alternative projection only under the same C18-controlled necessity and anti-copy rules as other projections;
4. reject unrestricted alternative text, rationale, chain-of-thought, hidden deliberation, arbitrary scores, debug payloads, open semantic status strings, and extension bags;
5. enforce closed consistency rules already implied by the accepted model, including observation before inference, inference before disposition, explicit uncertainty, and evaluator-condition compatibility with not-evaluated/insufficient states;
6. reject contradictory combinations rather than infer or repair meaning;
7. preserve `material difference != candidate deficiency`, `condition not satisfied != candidate deficiency`, `technical failure != semantic difference`, `contamination != semantic difference`, and `preservation success != semantic correctness`;
8. add no semantic field unless its removal or replacement by a reference would destroy an already accepted discrimination.

This authority permits validation of settled semantic relationships. It does not permit a new inference vocabulary, richer explanation, free-form rationale, or semantic redesign.
