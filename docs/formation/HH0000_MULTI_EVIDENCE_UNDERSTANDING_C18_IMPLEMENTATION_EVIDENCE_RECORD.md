## 3. Implemented Responsibility Boundary

### 3.1 One comparison per record

Each finalized C18 evidence record has one stable comparison identity and links one or more exact candidate references used together in one comparison to the exact held-out requirement reference under one evaluator, comparison rule, cycle, and C12 capture.

Collections exist only as the existing `semanticEvaluation.comparisonRecords` result array. Records do not share or aggregate observation, inference, disposition, disagreement, uncertainty, or projection admission.

### 3.2 Exact provenance

Each finalized record requires:

1. comparison and cycle identity;
2. C12 candidate-capture identity derived from cycle identity and the immutable candidate structural digest;
3. exact candidate paths with immutable value digests;
4. held-out assessment identity, version, and C16 verified hash;
5. exact held-out requirement paths with immutable value digests;
6. evaluator identity/version;
7. comparison-rule identity/version;
8. identity-only C20 invocation linkage;
9. explicit finalization state and immutable seal.

### 3.3 Closed semantic layers

The implementation keeps separate closed structures for:

1. selected material dimensions;
2. literal observation class;
3. bounded inference class;
4. semantic disposition;
5. evaluator-condition status;
6. disagreement and credible alternatives;
7. uncertainty and insufficiency;
8. technical complete/incomplete finalization.

No candidate-failure field exists. C21 contamination and C23/C24 preservation remain outside the C18 record.

## 4. Projection-Admission Mechanism

### 4.1 Default

The default is `REFERENCE_ONLY`. A side in reference-only mode is invalid if any projection is present.

### 4.2 Admission

A projection requires a distinct `PROJECTION_REQUIRED` admission containing:

1. one exhaustive closed necessity reason;
2. one exact allowed scope;
3. selected allowed material dimensions;
4. a positive bounded character limit no greater than 512;
5. the separately supplied exact immutable reference.

The closed necessity concepts are limited to:

1. the reference scope exceeds the comparison scope;
2. the reference does not preserve the applied material meaning;
3. the governed rule requires a projection.

Open reasons such as convenience, readability, debugging, preference, or possible future usefulness are rejected.

### 4.3 Scope enforcement

Validation rejects absent admission, open reasons, mismatched scope, mismatched material dimensions, empty projection, over-limit projection, unknown projection fields, and projection in reference-only mode.

When projection is declared necessary but unavailable, finalization succeeds only with:

1. unable-to-observe observation;
2. indeterminate inference;
3. comparison-insufficient disposition;
4. evaluator condition not determinable;
5. explicit projection-required-but-unavailable uncertainty.

No wider capture is attempted.
