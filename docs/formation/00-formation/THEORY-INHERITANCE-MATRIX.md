# Theory Inheritance Matrix

> Here is the revised inheritance methodology.

## Revised methodology

Not every theory should be validated in the same way. Theories fall into three classes.

### 1. Implemented theories
These are implemented directly as runtime capabilities.

Examples:
- Memory
- Knowledge
- Understanding
- Context
- Investigation
- Deliberation

Validation method:
- implementation
- tests
- evidence

### 2. Orchestrated theories
These emerge through the interaction of multiple implemented capabilities.

Examples:
- Judgement
- Awareness
- Compass
- Moral Compass
- Authority

Validation method:
- correct orchestration
- runtime behaviour
- evidence

### 3. Demonstrated theories
These are not separate modules. They are demonstrated through consistent behaviour over time.

Examples:
- Wisdom (Theory 006)
- Trust
- Character
- Stewardship

These should not be marked partial simply because no standalone runtime module exists. They should be assessed by behavioural evidence.

## Revised validation model

For every theory, record:
- Validation Class
  - Implemented
  - Orchestrated
  - Demonstrated
- Validation Method
  - Code
  - Behaviour
  - Evidence
  - Human review

## Theory 006 reassessment

Theory 006 is validated by demonstration.

Evidence supporting behavioural inheritance includes:
- asking the most important question before answering;
- choosing restraint when evidence is insufficient;
- balancing competing evidence;
- recognising consequences;
- preserving people before process;
- refusing to overclaim certainty;
- recognising when no recommendation should yet be made;
- remaining consistent with the Constitution.

No Wisdom.ts module is required.

## Notes on misclassification

The following theories were previously being assessed through the wrong model:
- Theory 006 — Wisdom was treated as if it required a module.
- Theory 008 — Trust was treated too much as a module-like capability rather than as a demonstrated behavioural pattern.
- Theory 009 — Transformation was treated as if it should be represented by a dedicated runtime module rather than by a synthesis path.
- Theory 005 — Learning was treated as if full inheritance required a dedicated learning engine rather than persistent behavioural refinement.
