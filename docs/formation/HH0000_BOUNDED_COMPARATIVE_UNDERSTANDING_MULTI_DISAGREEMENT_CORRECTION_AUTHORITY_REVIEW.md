## 6. Independent Defect Verification

Current private formation can add one `apparent-disagreement` for each governed metadata comparison group whose attributable values differ. Status, date, scope, and state can therefore produce multiple disagreement relationships in one supplied set.

Subsequent processing selects only:

```ts
const disagreement = relationships.find((relationship) => relationship.kind === "apparent-disagreement");
```

The selected value alone drives:

1. the exact relationship-relevance check;
2. qualification;
3. possible-supersession Inference;
4. unresolved-relationship formation;
5. explicit unresolved uncertainty;
6. the human-decision question.

Later disagreement relationships retain their initial uncertainty and are converted to Inferences by the final relationship loop, but they do not receive independent relevance or consequence evaluation. A relationship resolving the first disagreement can therefore coexist with an unprocessed later disagreement, and one generic unresolved result for the first cannot establish the correct boundary for another.

The defect is exactly the singular selection and its local consequence block. It is not in extraction, the accepted exact relevance helper, rendering, retrieval, persistence, or architecture.

## 7. Default Hypothesis Decision

The hypothesis is approved:

For each disagreement, formation must independently evaluate:

## 8. Relationship Independence Rules

The correction must preserve all of these rules:

1. an explicit relationship may resolve only a disagreement whose participating records it exactly identifies;
2. resolving one disagreement must not resolve another;
3. one unresolved disagreement must not create false unresolved status for a different explicitly resolved disagreement;

5. multiple materially distinct unresolved relationships may produce multiple human-decision questions;

## 9. Human-Decision Distinctness and Duplication

Every unresolved relationship must first be represented independently. Question omission is then permitted only when the implementation can demonstrate that two candidate questions refer to the same governed unresolved boundary.

Demonstrable sameness must use existing exact private provenance, such as the same unresolved relationship identity or the same exact supporting Observation-ID set and the same missing-decision basis. Similar wording, the same participating filenames, topic overlap, or a guess that one organisational decision would answer both is not sufficient.

Where status and state, or another pair of governed matters, require different decisions, both boundaries must remain visible. Existing `HumanDecisionQuestion` values already carry an `unresolvedRelationshipId`, while the linked relationship carries supporting Observation IDs, basis, and uncertainty. Question text can identify its linked formed boundary without a new field or rendering responsibility.

Because comparison groups already form one disagreement per group, no general semantic deduplication facility is justified. If exact sameness is not demonstrable, the correction must preserve both questions rather than silently merge them.
