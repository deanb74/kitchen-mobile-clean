# Theory Map

> Nothing is invented twice. Everything is inherited.

This document is the dependency graph of ideas within the Helping Hand Theory Library.

It is not a file index.

It is not an implementation.

It is the conceptual map that explains how the universal theories depend upon and inherit from one another.

---

## Conceptual Chain

```text
Experience
	│
	▼
Memory
(retains significance)
	│
	▼
Knowledge
(organises relationships)
	│
	▼
Understanding
(explains meaning)
	│
	▼
Judgement
(evaluates action)
	│
	▼
Learning
(improves capability)
	│
	▼
Wisdom
(generalises principles)
	│
	▼
Trust
(justifies confidence)

	  ▲
	  │
       Context
(governs every transformation)
```

Every stage performs a unique transformation.

Every stage inherits from every stage before it.

No stage replaces another.

No stage bypasses another.

---

## Context

Context is not another stage in the chain.

Context performs no transformation.

Instead, it governs every transformation.

Without context:

- experience remains unexamined,
- memory becomes ambiguous,
- knowledge becomes fragmented,
- understanding becomes incomplete,
- judgement becomes unreliable,
- learning becomes less transferable,
- wisdom loses grounding,
- consistent demonstration becomes inconsistent,
- trust becomes difficult to justify.

Context changes interpretation.

It does not change truth.

---

## Principles of Inheritance

Each theory inherits the capabilities established by every theory before it.

Earlier theories provide foundations.

Later theories extend those foundations.

No theory duplicates the responsibility of another.

Weakness introduced early in the chain propagates throughout every stage that follows.

This dependency is intentional.

It ensures that every future philosophy, architecture and engineering decision can be traced back to a stable theoretical foundation.

---

## Architectural Meaning

The Theory Map defines the conceptual architecture of the Theory Library.

It does not define software architecture.

It defines the dependency relationships between universal concepts.

The individual theory papers define each concept.

The Theory Map explains how those concepts form one coherent model.

---

## Capability Filter

The Theory Library provides a simple admissibility test for new capability ideas.

Before design or implementation, ask:

Does it belong inside the brackets?

```text
People (Helping Hand) People
```

If yes, continue.

If no, clarify why it exists.

Capabilities that do not improve what happens between people should not enter shared architecture.
